## 3. Qualitätstools nach tatsächlichem Bedarf

| Klasse | Werkzeuge | Begründung / Grenze |
|---|---|---|
| Ab erster Codebasis wesentlich | Gewählter Formatter/Linter/Typprüfung, echte Unit-/Vertragstests, Secrets-/Diff-/Lizenzprüfung | Erst Stack bestätigen: Python Ruff + mypy + pytest; TypeScript strict + ESLint + Prettier + Vitest. Keine parallelen redundanten Formatter/Typechecker |
| Ab zugehöriger Funktion | Playwright/Testing Library/axe, pip-audit oder npm audit, ein Updater (Dependabot **oder** Renovate), SBOM z. B. Syft | End-to-End nur kritische Flows; Advisoryverkehr/Updatepermissions und vollständige Transitive prüfen. Auditfund ist zu bewerten, kein garantierter Exploitnachweis |
| Früh sinnvoll, hier nicht installiert | Gitleaks bzw. gleichwertiger vorhandener Secretscanner, Markdown-/Link-/IDprüfung | Ein deterministischer Scanner ergänzt manuelle Diff-/Inhaltsprüfung; textliche Agentenregel allein schützt nicht |
| Optional bei Bedarf | Storybook, Lighthouse, lokale visuelle Regression, Trivy für spätere Container, Semgrep, OpenTelemetry | Keine SaaS-/Collectorplattform für persönlichen Prototyp erzwingen; Speichermengen/Logschutz und Scannerlizenz prüfen |
| Redundant / vorerst ungeeignet | mypy **und** pyright parallel, Dependabot **und** Renovate, mehrere Chart-/Primitiven-/Evalsuiten, neue Monitoringcluster | Mehr Updates und widersprechende Regeln ohne aktuellen Nutzen. pyright-Alternative nur als noch nicht separat lizenzverifiziert erwähnt, keine Empfehlung zur Installation |

Mypy ist hier die verifizierte Python-Typprüfoption; Gleichwertigkeit oder pyright-Lizenz nicht erfunden. npm audit ist CLI-/Registryfunktion, kein neues unabhängiges OSS-Auditpaket. GitHub Actions/Dependabot-Hostedprodukte unter eigenen Bedingungen, öffentliche Nutzung nicht automatisch kostenfrei oder freigegeben. Hostedscanner/Plugins können Quelltext exfiltrieren; lokale begrenzte Prüfung bevorzugen.
